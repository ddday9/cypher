# Клиент cypher: полное руководство

Здесь описано всё, что настраивается на стороне клиента: графический
клиент **nevio** для Windows, консольный клиент `cypher` (Windows и
Linux), формат ссылок, каждый параметр конфига, маршрутизация, режим TUN,
подключение через ретранслятор и диагностика. Сервер описан в
[server.md](server.md).

## 1. Какой клиент выбрать

| | nevio | `cypher` (консольный) |
|---|---|---|
| Система | Windows 10/11 | Windows, Linux (amd64, arm64) |
| Настройка | окно, ссылки и подписки | файл `config.json` |
| Системный прокси Windows | включает сам | вручную |
| Весь трафик (TUN) | кнопкой, `wintun.dll` встроен | `type: tun`, `wintun.dll` рядом |
| Правила по программам | выбор из запущенных | поле `process` |
| Несколько серверов в правилах | один активный сервер | сколько угодно outbound'ов |

Оба работают на одном ядре и одинаково маскируются.

## 2. nevio: установка и первый запуск

1. Скачайте `nevio-windows-amd64.exe` со страницы
   [Releases](https://github.com/ddday9/cypher/releases/latest) (или
   соберите: `make gui`).
2. Положите в любую папку, например `%LOCALAPPDATA%\nevio\`, и запустите.
   Нужен WebView2 Runtime (есть в Windows 10/11; без него интерфейс
   откроется в браузере).
3. **Серверы** → вставьте ссылку `cypher://…` (её печатает сервер) или
   адрес подписки `https://…` → **Добавить**.
4. **Главная** → большая кнопка. При первом подключении скачиваются базы
   geosite/geoip (~100 МБ).

Закрытие окна сворачивает nevio в трей. Меню значка: открыть,
подключить/отключить, переключить TUN, выход.

## 3. nevio: все экраны и настройки

### 3.1. Главная

* **Кнопка питания** — подключить/отключить. Под ней — статус и время
  подключения.
* **Режим** (переключатель): **Прокси** — через cypher идут программы,
  которые используют системный прокси (браузеры, большинство приложений);
  **Весь трафик (TUN)** — все программы, включая игры и UDP. Для TUN нужны
  права администратора: nevio предложит перезапуститься с ними (запрос
  UAC).
* **↑ / ↓** — скорость и объём отправленного и полученного.
* **Сервер** — выбранный сервер (нажмите, чтобы сменить) и его пинг.
* **Маршрутизация** — текущий пресет (нажмите, чтобы перейти в настройки).
* Плашка **«защита от заморозки»** — оператор замораживал соединения, и
  трафик сейчас идёт короткими соединениями (медленнее). См. 3.4.
* Баннер вверху — ошибки (например, сервер недоступен) и подсказки.

### 3.2. Серверы

* **Поле ввода** — ссылка `cypher://…`, несколько ссылок (по одной в
  строке) или адрес подписки `https://…`. **Из буфера** — вставить из
  буфера обмена.
* **Проверить пинг** — время TCP-подключения до каждого сервера (без
  TLS). «нет связи» — сервер недоступен, `—` — ещё не проверялся.
* **Обновить подписки** — перечитать все подписки. Выбранный сервер
  сохраняется, если он остался в подписке.
* У каждого сервера: выбор (кружок), **⧉** — скопировать ссылку, **✕** —
  удалить (у серверов из подписки удаления нет — они управляются
  подпиской).
* Пометка **«через ретранслятор, сквозное шифрование»** — в ссылке есть
  ключ выхода ([раздел 9](#9-через-ретранслятор)).

**Подписка** — URL, который отдаёт список ссылок `cypher://` (по одной в
строке) или тот же список в base64.

### 3.3. Настройки → Маршрутизация

**Пресет** — основа правил:

| Пресет | Что делает |
|---|---|
| **Россия напрямую** (по умолчанию) | реклама блокируется; российские сайты (`geosite:category-ru`, `.ru`, `.рф`, `.su`), локальная сеть и российские IP — напрямую; остальное — через VPN |
| **Только заблокированное** | реклама блокируется; через VPN только `geosite:ru-blocked` и `geoip:ru-blocked`; остальное — напрямую |
| **Всё через VPN** | всё, кроме локальной сети |
| **Только мои правила** | работают только приложения, «Мои правила» и расширенные правила; остальное — по выбору **Всё остальное**: «Через VPN» или «Напрямую» |

**Приложения** → **+ Добавить приложение**: выберите программу из
запущенных или впишите имя файла (`dota2.exe`) и действие: **Напрямую**,
**Через VPN**, **Блокировать**. Работает полностью в режиме TUN; в режиме
«Прокси» — только для программ, которые сами ходят через прокси (игры
обычно нет). Для Steam-игр обычно достаточно `dota2.exe`/`cs2.exe`, для
лаунчера — `steam.exe`.

**Мои правила** → **+ Добавить правило**: тип, значения через запятую,
действие (Через VPN / Напрямую / Блокировать):

| Тип | Пример значения | Что совпадает |
|---|---|---|
| Домен | `example.com` | домен и все поддомены |
| Точный домен | `www.example.com` | только этот домен |
| Слово в домене | `google` | подстрока |
| geosite | `youtube`, `category-ru` | категория из базы (без префикса `geosite:`) |
| IP / сеть | `1.2.3.4`, `10.0.0.0/8` | адрес или подсеть |
| geoip | `ru`, `private` | страна/категория из базы |
| Порт | `443`, `27000-27100` | порт назначения |
| Программа | `dota2.exe` | как «Приложения» |

**Расширенные правила (JSON)** — массив правил в формате Xray/cypher
([раздел 7](#7-маршрутизация)), действия `proxy`, `direct`, `block`:

```json
[
  { "domain": ["geosite:discord"], "network": "udp", "outbound": "proxy" },
  { "port": "3478-3481", "outbound": "direct" }
]
```

**Порядок проверки:** приложения → мои правила сверху вниз → расширенные
правила → пресет. Первое совпавшее правило решает. Ошибки (неверный IP,
несуществующая категория) показываются при сохранении.

### 3.4. Настройки → Подключение

| Настройка | Варианты | Что делает |
|---|---|---|
| **Системный прокси Windows** | вкл. (по умолчанию) / выкл. | в режиме «Прокси» nevio сам включает системный прокси и возвращает прежние настройки при отключении (даже после аварийного завершения — при следующем запуске) |
| **Отпечаток TLS** | **Firefox (по умолчанию)**, Chrome, Safari, Edge, iOS, Android, Случайный, Как в ссылке сервера | каким браузером nevio выглядит для DPI. «Случайный» выбирается один раз для пары «ключ + сервер» из Firefox, Edge, Android и не меняется. По наблюдениям 2026 года Firefox, Edge и Android проходят проверку ТСПУ лучше Chrome, Safari, iOS |
| **Соединения** | Пул с ротацией (по умолчанию) / Одно соединение | «Одно» — строго одно TLS-соединение к серверу всегда, без перекрытия при ротации; защита от заморозки при этом выключена |
| **Защита от заморозки** | Авто (по умолчанию) / Всегда / Выключена | при заморозке соединения оператором (~16 КБ к зарубежным хостингам) — короткие соединения. «Авто» включает её на 30 минут, если заморозка повторилась в течение 10 минут |
| **Скорость защиты** | Осторожно (8 соединений / 10 с, ≈6 КБ/с) / Быстрее (20, ≈16 КБ/с) / Без ограничения | сколько новых соединений можно открывать в режиме защиты; некоторые провайдеры блокируют сервер за частые подключения |
| **Порт SOCKS5** | 10808 | локальный SOCKS5-прокси (127.0.0.1) для программ, где его можно указать |
| **Порт HTTP** | 10809 | локальный HTTP-прокси; его nevio прописывает в системный прокси |

Настройки отпечатка, соединений и защиты действуют для всех серверов
(перекрывают параметры из ссылок), кроме «Как в ссылке сервера».

### 3.5. Настройки → Базы geosite / geoip

| Настройка | Что делает |
|---|---|
| **Источник** | **runetfreedom** (по умолчанию; нужен пресетам про Россию: `ru-blocked`, `category-ru`), **Loyalsoldier**, **v2fly** или **Свои ссылки** (адреса `geosite.dat` и `geoip.dat`) |
| **Обновлять** | каждые 6 / 12 часов, раз в сутки (по умолчанию), раз в 3 дня, раз в неделю, не обновлять |
| **Обновить сейчас** | скачать сразу; рядом — время последнего обновления |

Обновление баз не рвёт подключение: правила подменяются на лету.

### 3.6. Настройки → Приложение

| Настройка | Что делает |
|---|---|
| **Запускать вместе с Windows** | автозапуск при входе в систему |
| **Подключаться при запуске** | сразу подключаться к выбранному серверу |
| **Подробность логов** | Ошибки / Предупреждения / Обычная / Отладка (с адресами соединений — для диагностики) |

**Сохранить** — применить. Если nevio подключён, он сразу
переподключается с новыми настройками (это занимает секунду). Обновление
баз geosite/geoip само по себе соединение не рвёт.

### 3.7. Логи

Последние строки лога и кнопка **Копировать** (для вопросов и
диагностики).

### 3.8. Где лежат данные

`%APPDATA%\nevio\`: `state.json` (серверы, подписки, настройки — содержит
ключи, не публикуйте), `geosite.dat`, `geoip.dat`, `nevio.log`,
`sysproxy.json` (сохранённые настройки системного прокси на время
подключения), `webview2\` (данные окна). Перенос на другой компьютер —
скопируйте `state.json`.

## 4. Ссылка cypher://

```
cypher://КЛЮЧ@хост:порт?параметры#имя
```

| Часть | Пример | Что это |
|---|---|---|
| `КЛЮЧ` | `3gG7d0OF…` | ключ пользователя (43 символа base64url) |
| `хост:порт` | `exit.example.com:443` | сервер; без порта — 443 |
| `#имя` | `#exit.example.com%20·%20phone` | отображаемое имя (URL-кодированное) |
| `sni` | `sni=cdn.example.com` | TLS SNI, если отличается от хоста |
| `fp` | `fp=firefox` | отпечаток: `firefox`, `chrome`, `safari`, `edge`, `ios`, `android`, `random` |
| `conn` | `conn=2` | соединений параллельно (1–16) |
| `af` | `af=auto` | защита от заморозки: `auto`, `on`, `off` |
| `sc` | `sc=1` | строго одно соединение |
| `ek` | `ek=…` | ключ пользователя на выходе — сквозное шифрование через ретранслятор |
| `epk` | `epk=…` | публичный ключ выхода (сервер v0.3+ пишет его во все ссылки) |
| `hd` | `hd=1` | скрыть адреса от ретранслятора |

Неизвестные параметры игнорируются, поэтому новые ссылки открываются и в
старых клиентах (без новых возможностей).

Собрать ссылку вручную:

```bash
cypher link -server exit.example.com:443 -key КЛЮЧ -name "Мой сервер"
```

| Флаг | Что это |
|---|---|
| `-server HOST:PORT` | сервер (обязательно) |
| `-key KEY` | ключ (обязательно) |
| `-name NAME` | имя |
| `-sni NAME` | SNI |
| `-fp NAME` | отпечаток |
| `-af auto\|on\|off` | защита от заморозки |
| `-single` | строго одно соединение |
| `-exit-key KEY`, `-exit-pub KEY` | сквозное шифрование через ретранслятор (вместе) |
| `-hide` | скрыть адреса от ретранслятора |

## 5. Консольный клиент: установка и запуск

### 5.1. Windows

1. Распакуйте `cypher-windows-amd64.zip` ([Releases](https://github.com/ddday9/cypher/releases/latest))
   в папку, например `C:\cypher` (внутри `cypher.exe` и `examples\`).
2. Скопируйте `examples/client.json` в `C:\cypher\client.json`, впишите
   `server` и `key` (из ссылки: `cypher://КЛЮЧ@СЕРВЕР`).
3. Проверьте и запустите:

```bash
cypher.exe check -c client.json
```

```bash
cypher.exe run -c client.json
```

4. Системный прокси: **Параметры → Сеть и Интернет → Прокси-сервер →
   Использовать прокси-сервер**, адрес `127.0.0.1`, порт `10809`. Или
   SOCKS5 `127.0.0.1:10808` в настройках программы.

Для TUN — `wintun.dll` (с [wintun.net](https://www.wintun.net),
`wintun\bin\amd64\wintun.dll`) рядом с `cypher.exe`, конфиг на основе
`examples/client-tun.json`, запуск от администратора.

### 5.2. Linux

```bash
tar xzf cypher-linux-amd64.tar.gz && sudo install cypher-linux-amd64/cypher /usr/local/bin/cypher
```

(для ARM — `cypher-linux-arm64.tar.gz`).

```bash
cypher run -c client.json
```

TUN — от root или с `CAP_NET_ADMIN`; с systemd-resolved DNS направляется
в TUN через `resolvectl`.

Базы geosite/geoip скачиваются сами (из runetfreedom), если правила их
используют. Остановка — Ctrl+C.

### 5.3. Команды

| Команда | Что делает |
|---|---|
| `cypher run -c FILE` | запустить (по умолчанию `config.json`) |
| `cypher check -c FILE` | проверить конфиг (inbounds, outbounds, правила) и выйти |
| `cypher link …` | собрать ссылку ([раздел 4](#4-ссылка-cypher)) |
| `cypher genkey` | новый ключ |
| `cypher version` | версия |

## 6. config.json — все параметры

```json
{
  "log": { "level": "info" },
  "inbounds": [ … ],
  "outbounds": [ … ],
  "routing": { … }
}
```

Неизвестные поля — ошибка. Относительные пути считаются от папки конфига
(затем — от папки программы).

### 6.1. log

| Поле | По умолчанию | Значения |
|---|---|---|
| `level` | `info` | `debug` (каждое соединение и выбранный маршрут), `info`, `warn`, `error` |

### 6.2. inbounds — откуда принимать трафик

Общие поля:

| Поле | Что это |
|---|---|
| `tag` | имя (для правил `inboundTag`); по умолчанию `<тип>-<номер>` |
| `type` | `socks`, `http`, `tun` |

**socks** — SOCKS5 без пароля, с поддержкой UDP (UDP ASSOCIATE):

| Поле | Пример |
|---|---|
| `listen` (обязательно) | `127.0.0.1:10808` |

**http** — HTTP-прокси (CONNECT и обычные запросы):

| Поле | Пример |
|---|---|
| `listen` (обязательно) | `127.0.0.1:10809` |

Не открывайте `listen` на `0.0.0.0` без необходимости: прокси без пароля
будет доступен всей сети.

**tun** — весь трафик системы ([раздел 8](#8-режим-tun)):

| Поле | По умолчанию | Что это |
|---|---|---|
| `name` | `cypher` | имя сетевого адаптера |
| `mtu` | `1500` | MTU |
| `address` | `172.19.0.1/30` | IPv4-адрес адаптера |
| `address6` | `fdfe:dcba:9876::1/126` | IPv6-адрес; `"off"` — без IPv6 |
| `autoRoute` | `true` | направить маршруты в адаптер |
| `routes` | всё (`0.0.0.0/1`, `128.0.0.0/1`, IPv6) | какие сети направлять |
| `dnsHijack` | `1.1.1.1:53` | все DNS-запросы (порт 53 на любой адрес) уходят сюда по правилам маршрутизации (обычно через туннель); `"off"` — не перехватывать |
| `sniff` | `true` | брать домен из SNI (TLS) и Host (HTTP), чтобы работали доменные правила для соединений по IP |

### 6.3. outbounds — куда отправлять трафик

| Поле | Что это |
|---|---|
| `tag` (обязательно) | имя для правил (`proxy`, `direct`, `block` или любое своё) |
| `type` | `cypher`, `direct` (`freedom`), `block` (`blackhole`) |

`direct` — подключение напрямую с этого компьютера. `block` — отказ.

**cypher** — туннель до сервера:

| Поле | По умолчанию | Что это |
|---|---|---|
| `server` (обязательно) | — | `host:port` сервера |
| `key` (обязательно) | — | ключ пользователя |
| `serverName` | хост из `server` | SNI, если отличается |
| `fingerprint` | `firefox` | отпечаток ClientHello: `firefox`, `chrome`, `safari`, `edge`, `ios`, `android`, `random` (один раз по ключу и серверу из Firefox/Edge/Android) |
| `ca` | системные | доп. корневой сертификат (PEM) — для самоподписанного сервера |
| `insecure` | `false` | не проверять сертификат — **только для тестов** |
| `connections` | `1` | сколько TLS-соединений держать параллельно; новые потоки идут в наименее загруженное |
| `singleConnection` | `false` | строго одно соединение (см. ниже) |
| `rotation` | см. ниже | когда менять соединения |
| `antiFreeze` | `auto` | защита от заморозки: `auto`, `on` (`always`), `off` (`never`) |
| `antiFreezeRate` | `8` | новых соединений за 10 с в режиме защиты |
| `exitKey` | — | ключ пользователя на выходе — сквозное шифрование через ретранслятор |
| `exitPublicKey` | — | публичный ключ выхода (`epk`) |
| `hideDestinations` | `false` | не показывать ретранслятору адреса (он отправит всё на выход) |

**rotation** — каждое соединение выбирает свои случайные пределы из
диапазонов:

| Поле | По умолчанию | Что это |
|---|---|---|
| `age` | `"5m-20m"` | срок жизни соединения |
| `megabytes` | `"64-512"` | объём, после которого соединение меняется |
| `idle` | `"1m-3m"` | закрыть соединение без потоков после такого простоя |
| `disabled` | `false` | не ротировать (соединение живёт до обрыва) |

Значение может быть одним числом (`"10m"`, `"100"`) или диапазоном. Когда
предел достигнут, соединение больше не получает новых потоков и
закрывается, когда допишут текущие (не позже чем через час). С
`singleConnection` новое соединение открывается только после закрытия
старого.

Что клиент делает всегда, независимо от настроек: не больше одного
TLS-хендшейка одновременно, между хендшейками ≥ 1 с и не больше трёх в
минуту; после неудачного подключения — пауза 2 с, 4 с, … до 2 минут;
keepalive — через случайные 10–40 с; отпечаток у соединений одного
сервера одинаковый.

### 6.4. routing

| Поле | По умолчанию | Что это |
|---|---|---|
| `geosite`, `geoip` | `geosite.dat`, `geoip.dat` | пути к базам |
| `geositeURL`, `geoipURL` | runetfreedom, если правила используют `geosite:`/`geoip:` | откуда скачивать; `"none"` — не скачивать |
| `geoUpdate` | `24h` | период обновления: `6h`, `12h`, `72h` …, `off` |
| `domainStrategy` | `AsIs` | `AsIs` или `IPIfNonMatch` ([7.4](#74-domainstrategy)) |
| `rules` | — | правила по порядку |
| `default` | первый outbound | куда, если ничего не совпало |

## 7. Маршрутизация

### 7.1. Как проверяются правила

Правила проверяются сверху вниз, первое совпавшее определяет `outbound`.
Внутри одного поля значения объединяются через ИЛИ, разные поля одного
правила — через И. Если ничего не совпало — `default`.

```json
{ "domain": ["geosite:youtube", "domain:googlevideo.com"], "network": "tcp", "outbound": "proxy" }
```

— YouTube **или** googlevideo, **и** при этом TCP.

### 7.2. Поля правила

| Поле | Пример | Что совпадает |
|---|---|---|
| `domain` | `["geosite:google", "domain:example.com"]` | домен назначения |
| `ip` | `["geoip:ru", "10.0.0.0/8"]` | IP назначения |
| `port` | `443`, `"80,443"`, `"1000-2000"` | порт |
| `network` | `"tcp"`, `"udp"`, `"tcp,udp"` | протокол |
| `inboundTag` | `["socks"]` | через какой inbound пришло соединение |
| `process` | `["dota2.exe", "C:\\Games\\game.exe"]` | программа (имя файла без учёта регистра или полный путь); работает в TUN и для программ, идущих через прокси |
| `outbound` (обязательно) | `"proxy"` | tag outbound'а |

### 7.3. Синтаксис доменов и IP

| Запись | Совпадает |
|---|---|
| `geosite:google` | категория из geosite.dat |
| `geosite:google@cn` | категория с атрибутом |
| `domain:example.com` | домен и все поддомены |
| `full:www.example.com` | только этот домен |
| `keyword:goog` | подстрока |
| `regexp:^ads\d+\.` | регулярное выражение |
| `example` | без префикса = `keyword:` |
| `geoip:ru`, `geoip:private` | страна / категория из geoip.dat |
| `geoip:!ru` | всё, кроме |
| `10.0.0.0/8`, `1.2.3.4`, `2001:db8::/32` | сеть или адрес |

Категории runetfreedom: `ru-blocked`, `ru-blocked-all`,
`ru-available-only-inside`, `category-ru`, `category-gov-ru`,
`category-ads-all`, `private` (geosite); `ru`, `ru-blocked`,
`ru-blocked-community`, `private` (geoip); плюс все категории v2fly.

### 7.4. domainStrategy

* `AsIs` — IP-правила применяются только к соединениям по IP.
* `IPIfNonMatch` — если домен не совпал ни с одним правилом, клиент
  резолвит его и проверяет IP-правила (например, `geoip:ru`).
  **Внимание:** это локальный DNS-запрос к провайдеру, он раскрывает
  домен.

### 7.5. Несколько серверов

Outbound'ов `cypher` может быть несколько, правила выбирают между ними:

```json
"outbounds": [
  { "tag": "nl", "type": "cypher", "server": "nl.example.com:443", "key": "…" },
  { "tag": "us", "type": "cypher", "server": "us.example.com:443", "key": "…" },
  { "tag": "direct", "type": "direct" }
],
"routing": {
  "rules": [ { "domain": ["geosite:netflix"], "outbound": "us" } ],
  "default": "nl"
}
```

## 8. Режим TUN

Через cypher идёт весь трафик системы.

* Создаётся адаптер `cypher`, в него направляются `0.0.0.0/1`,
  `128.0.0.0/1` (и IPv6). Основной маршрут не трогается — после выхода
  сеть остаётся как была. Локальная сеть идёт мимо TUN.
* Соединения самого cypher (к серверу и `direct`) привязываются к
  физическому интерфейсу и не зацикливаются; смена Wi-Fi ↔ кабель
  отслеживается.
* Адрес сервера резолвится один раз при старте.
* **DNS:** все запросы на порт 53 перехватываются и уходят на `dnsHijack`
  по правилам (обычно через туннель) — провайдер их не видит.
* **Sniff:** домен для правил `geosite:` берётся из SNI/Host.

Ограничения: ICMP (ping) через TUN не проходит; домен для правил берётся
только из TCP (TLS/HTTP), QUIC маршрутизируется по IP; Windows иногда
спрашивает DNS и у физического адаптера — чтобы исключить, отключите
групповой политикой «Конфигурация компьютера → Административные шаблоны →
Сеть → DNS-клиент → Отключить интеллектуальное разрешение многоадресных
имён».

## 9. Через ретранслятор

Ретранслятор — сервер в России перед зарубежным выходом
([server.md, раздел 8](server.md#8-ретранслятор-промежуточный-сервер)).
Для клиента это просто другая ссылка.

* **Ссылка без `ek`** (режим A) — ретранслятор расшифровывает трафик и сам
  решает, что отправить напрямую, а что на выход. Работает в любом клиенте.
* **Ссылка с `ek` и `epk`** (режим B) — трафик на выход шифруется ключом
  выхода; ретранслятор видит только адрес (для своих правил), но не
  данные. В nevio такой сервер помечен «через ретранслятор, сквозное
  шифрование». В конфиге — `exitKey` и `exitPublicKey`.
* **`hd=1`** / `hideDestinations` — ретранслятор не видит и адресов; всё
  идёт на выход.

Правила клиента применяются первыми: что клиент отправил «напрямую», до
ретранслятора не доходит. Прямое подключение к выходу (его собственная
ссылка) работает параллельно — держите его как запасной сервер.

Пример outbound'а:

```json
{ "tag": "proxy", "type": "cypher", "server": "ru.example.com:443", "key": "КЛЮЧ_НА_РЕТРАНСЛЯТОРЕ",
  "exitKey": "КЛЮЧ_НА_ВЫХОДЕ", "exitPublicKey": "EPK_ВЫХОДА" }
```

## 10. Защита от блокировок: что и когда включать

| Ситуация | Что сделать |
|---|---|
| Обычная работа | ничего: Firefox, пул с ротацией, `antiFreeze: auto` |
| Сайты открываются через раз, загрузки висят на мобильной сети (заморозка ~16 КБ) | `antiFreeze: auto` справится сам; если часто — `on`; надёжнее — ретранслятор в РФ |
| Новые подключения к серверу перестают проходить на минуты | не меняйте отпечаток в этот момент (продлевает блок); проверьте, не включён ли `antiFreeze: on` с большой скоростью; попробуйте «Одно соединение» |
| Хотите минимум параллельных подключений | `singleConnection: true` («Одно соединение») |
| Блокируют зарубежный IP целиком | ретранслятор в РФ или другой хостинг |
| Сервер видит российские сайты с вашим трафиком | пресет «Россия напрямую» (по умолчанию) отправляет их мимо сервера |

Подробности о методах блокировок и о том, от чего cypher защищает, — в
[comparison.md](comparison.md).

## 11. Что применяется без перезапуска

Консольный клиент каждые 3 секунды проверяет конфиг и базы. Если файл
изменился (и не меняется ещё одну проверку), правила маршрутизации
пересобираются на лету; открытые соединения не рвутся. Ошибка в новом
конфиге или базе — в лог, действуют старые правила.

На лету меняется только секция `routing` и файлы баз. Изменения
`inbounds`, `outbounds`, `geositeURL`/`geoipURL`/`geoUpdate` требуют
перезапуска.

## 13. Диагностика

Логи: nevio — экран «Логи» (для подробностей — «Отладка» в настройках);
консольный клиент — вывод в терминал, `"log": {"level": "debug"}`.

| Симптом / сообщение | Что делать |
|---|---|
| `server unreachable, next attempt in …` | сервер недоступен; клиент сам повторит через указанное время. Проверьте адрес, порт, интернет |
| `tls handshake: …certificate…` | неверный домен в ссылке, сервер ещё не получил сертификат, или самоподписанный сертификат без `ca` |
| Подключено, но сайты не открываются | неверный ключ (сервер отдаёт сайт-прикрытие), или время на компьютере расходится больше чем на 2 минуты |
| `server: destination not allowed` | адрес запрещён правилами сервера или это локальный адрес сервера |
| `end-to-end encryption with the exit: …` | неверный `ek`/`epk` или пользователь отозван на выходе: возьмите новую ссылку |
| `tunnel frozen (no answer from the server), reconnecting` | оператор заморозил соединение; переподключение автоматическое, при повторах включится защита от заморозки |
| Не работают правила `geosite:` | базы ещё не скачаны или нет доступа к GitHub: «Обновить сейчас» в nevio, либо положите файлы вручную и `"geositeURL": "none"` |
| Игра идёт не туда | правило по программе работает в TUN; в режиме «Прокси» игра обычно идёт напрямую мимо cypher |
| В TUN нет интернета после аварийного выхода | перезапустите nevio/cypher — адаптер и маршруты удаляются при выходе; в крайнем случае перезагрузите компьютер |

Проверить сервер с Linux: `./deploy/test-client.sh --server ХОСТ:443 --key КЛЮЧ`
([server.md, 14.7](server.md#147-проверить-сервер-с-другого-linux-хоста)).
