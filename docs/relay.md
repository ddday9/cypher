# Ретранслятор внутри страны

Обзор. Все параметры и шаги — в [server.md, раздел 8](server.md#8-ретранслятор-промежуточный-сервер).

```
                      ┌──── российские сайты: напрямую с российского IP
клиент ──cypher──► [ретранслятор в РФ] ══ одно общее соединение ══► [выход за границей] ──► интернет
 (nevio)              маршрутизация geosite/geoip
```

Клиент подключается к серверу в России, тот по правилам решает, куда
отправить соединение: напрямую (российские сайты — со своего российского
IP) или дальше на выходной сервер за границей. Все пользователи идут к выходу
по одному общему мультиплексированному соединению.

Что это даёт: у клиента в трафике только российский IP, поэтому ограничения
«к зарубежным хостингам» (заморозка ~16 КБ и т. п.) его не касаются; IP
выхода не виден провайдеру клиента; если выход заблокируют, меняется одна
настройка на ретрансляторе, клиенты ничего не перенастраивают. Чего не даёт:
белые списки на мобильных пропускают конкретные адреса, а не любой
российский хостинг, — см. [сравнение](comparison.md).

Прямое подключение к выходу продолжает работать как раньше: ретранслятор —
дополнительный путь, а не замена.

## Два режима

| | Обычный (A) | Сквозное шифрование (B) |
|---|---|---|
| Ссылка | `cypher user add NAME` на ретрансляторе | то же плюс `-exit …` (ключ пользователя на выходе) |
| Клиенты | любые, даже v0.1 | nevio / cypher v0.3+ |
| Ретранслятор видит адреса назначения | да | да (нужно для маршрутизации); с `hd=1` — нет |
| Ретранслятор видит содержимое | да (HTTPS сайтов — всё равно зашифрован) | **нет**: шифротекст для выхода |
| Ретранслятор может подменить данные или выдать себя за пользователя на выходе | да | **нет** |
| Выход видит пользователя | общего пользователя ретранслятора | самого пользователя (его правила, отзыв) |

В режиме B каждый поток к выходу дополнительно шифруется Noise NK
(X25519, ChaCha20-Poly1305, BLAKE2s) ключом выхода, который клиент знает из
ссылки. Ретранслятор только пересылает байты. На ретрансляторе нет ни ключей
выхода, ни расшифрованного трафика, который идёт на выход.

Соединения, которые ретранслятор по правилам отправляет напрямую (российские
сайты), он, разумеется, обслуживает сам — как обычный сервер.

`hd=1` в ссылке (`hideDestinations`): ретранслятор не видит даже адресов, но
и маршрутизировать не может — всё идёт на выход. Нужен выход v0.3+.

## Установка в Docker

Нужны две ВМ, у каждой свой домен: выход за границей и ретранслятор в РФ.

**1. Выход** — как обычно ([docker.md](docker.md)). Создайте на нём
пользователя для ретранслятора:

```bash
docker compose exec cypher cypher user add relay
```

Ссылка вида `cypher://…@exit.example.com:443?epk=…` — это `CYPHER_UPSTREAM`
для ретранслятора (`epk` — публичный ключ выхода для сквозного шифрования).

**2. Ретранслятор** — та же папка `deploy/docker`, в `.env`:

```bash
CYPHER_DOMAIN=relay.example.ru
CYPHER_UPSTREAM=cypher://…ссылка пользователя relay с выхода…
```

```bash
docker compose up -d
```

**3. Пользователи.** Обычный режим (A) — на ретрансляторе:

```bash
docker compose exec cypher cypher user add phone
```

Сквозное шифрование (B) — пользователь заводится на обоих серверах: на
выходе (его ключ знает только выход) и на ретрансляторе:

```bash
docker compose exec cypher cypher user add phone
```

(на выходе; скопируйте ссылку), затем на ретрансляторе:

```bash
docker compose exec cypher cypher user add phone -exit "ССЫЛКА_С_ВЫХОДА"
```

Получившуюся ссылку (`…?ek=…&epk=…`) вставьте в nevio. В списке серверов
он будет помечен «через ретранслятор, сквозное шифрование». Отозвать доступ
можно на любом из двух серверов.

Без Docker: `sudo ./deploy/install-server.sh --domain relay.example.ru --upstream "ССЫЛКА"`.

## Маршрутизация на ретрансляторе

По умолчанию (создаётся при первом запуске с `CYPHER_UPSTREAM`), базы — из
[runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat),
обновляются раз в сутки встроенным таймером:

```json
"routing": {
  "geositeURL": "https://github.com/runetfreedom/russia-v2ray-rules-dat/releases/latest/download/geosite.dat",
  "geoipURL": "https://github.com/runetfreedom/russia-v2ray-rules-dat/releases/latest/download/geoip.dat",
  "rules": [
    { "domain": ["geosite:ru-blocked"], "outbound": "exit" },
    { "ip": ["geoip:ru-blocked"], "outbound": "exit" },
    { "domain": ["geosite:category-ru", "geosite:ru-available-only-inside", "domain:ru", "domain:xn--p1ai", "domain:su"], "outbound": "direct" },
    { "ip": ["geoip:ru"], "outbound": "direct" }
  ],
  "default": "exit"
}
```

То, что заблокировано в РФ, — через выход; российские сайты — напрямую с
ретранслятора; всё остальное — через выход. Действия: `direct`, `exit`,
`block`. `inboundTag` — имя пользователя на ретрансляторе. Синтаксис правил —
как у клиента ([setup.md](setup.md#маршрутизация)); изменения
`/etc/cypher/server.json` и новые базы применяются без перезапуска. Если
`geositeURL`/`geoipURL` не указаны, а правила используют `geosite:`/`geoip:`,
базы берутся из runetfreedom; `"none"` — не скачивать.

Правила клиента работают как раньше и проверяются первыми: в nevio
«Россия — напрямую» отправляет российские сайты прямо с компьютера, мимо
ретранслятора.

UDP маршрутизируется по каждому пакету в режиме A; в режиме B — по
первому адресату потока.

## Совместимость

| Клиент | Ретранслятор | Выход | Работает |
|---|---|---|---|
| любой, ссылка ретранслятора | v0.3 | v0.3 | режим A |
| v0.3, ссылка с `ek/epk` | v0.3 | v0.3 | режим B |
| v0.3, ссылка с `ek/epk` | v0.3 | v0.1–v0.2 | режим A (ретранслятор сам переходит на него) |
| v0.3, ссылка с `ek/epk` | обычный сервер (не ретранслятор) | — | как прямое подключение |
| любой | — | v0.3 | прямое подключение, как раньше |
