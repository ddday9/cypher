## 1. Роли сервера

Один и тот же бинарник `cypher` работает в двух ролях.

| Роль | Где стоит | Что делает | Как включается |
|---|---|---|---|
| **Выход** (обычный сервер) | за границей | принимает клиентов и выпускает их трафик в интернет | по умолчанию |
| **Ретранслятор** (промежуточный) | в России | принимает клиентов и по правилам отправляет трафик либо в интернет сам, либо на выход | параметр `server.upstream` (в Docker — `CYPHER_UPSTREAM`) |

```
клиент ──► выход ──► интернет                               (прямая схема)

клиент ──► ретранслятор ──┬──► интернет (российские сайты, с российского IP)
                          └══► выход ──► интернет (остальное)   (через ретранслятор)
```

Выход одновременно обслуживает и прямых клиентов, и ретрансляторы: прямую
схему можно держать как запасную.

В обеих ролях сервер снаружи выглядит как обычный сайт: TLS 1.3 с
настоящим сертификатом Let's Encrypt на ваш домен. Кто подключается без
ключа (браузер, поисковик, цензор), получает сайт-прикрытие.

## 2. Что нужно заранее

* **ВМ с публичным IPv4**, Linux (x86-64 или arm64). Для ретранслятора —
  ВМ в России; для выхода — за границей. Хватает 1 vCPU и 512 МБ ОЗУ
  (на ретрансляторе с базами geosite лучше от 1 ГБ: база runetfreedom
  весит ~90 МБ).
* **Домен на каждый сервер.** A-запись домена указывает на IP ВМ.
  Подойдёт поддомен (`exit.example.com`, `ru.example.com`).
* **Открытые входящие TCP-порты 80 и 443**, на которых больше ничего не
  слушает. 80 нужен только для получения сертификата и редиректа на https.
* Docker с плагином compose (для способа 3) или systemd (для способа 4).

## 3. Установка в Docker

Рекомендуемый способ. Запускаются два контейнера: `cypher` (порт 443) и
`nginx` (порт 80 и сайт-прикрытие внутри).

```
интернет ──:80──►  nginx   (редирект на https; проверки Let's Encrypt → cypher:8081)
         ──:443─►  cypher  ── клиент с ключом ──► туннель
                      └──── все остальные ──► nginx:8080 (сайт из ./site)
```

### 3.1. Скачать файлы

```bash
mkdir -p ~/cypher && cd ~/cypher && curl -sSL https://github.com/ddday9/cypher/releases/latest/download/cypher-linux-amd64.tar.gz | tar xz --strip-components=3 --wildcards '*/deploy/docker'
```

В папке появятся `docker-compose.yml`, `nginx.conf` и `site/`.

### 3.2. Файл .env

Все настройки первого запуска — в `.env` рядом с `docker-compose.yml`.

Выход:

```bash
CYPHER_DOMAIN=exit.example.com
CYPHER_EMAIL=you@example.com
```

Ретранслятор (как получить ссылку — в [разделе 8](#8-ретранслятор-промежуточный-сервер)):

```bash
CYPHER_DOMAIN=ru.example.com
CYPHER_UPSTREAM=cypher://КЛЮЧ@exit.example.com:443?epk=…
```

Переменные, которые передаёт `docker-compose.yml`:

| Переменная в .env | Обязательна | Что это |
|---|---|---|
| `CYPHER_DOMAIN` | да | домен этого сервера |
| `CYPHER_EMAIL` | нет | email для уведомлений Let's Encrypt |
| `CYPHER_BLOCK_RU` | нет | `1` — выход не ходит на российские сайты и IP (см. [14.6](#146-не-светить-ip-выхода-на-российских-сайтах)) |
| `CYPHER_UPSTREAM` | для ретранслятора | ссылка пользователя на выходе — сервер станет ретранслятором |

Остальные переменные ([раздел 11](#11-переменные-окружения)) можно
добавить в секцию `environment` файла `docker-compose.yml`.

**Важно:** переменные используются **только при первом запуске**, когда в
томе ещё нет конфига. Дальше всё берётся из `/etc/cypher/server.json` в
томе `cypher_cypher-data`, и изменение `.env` ни на что не влияет — правьте
конфиг ([3.5](#35-редактирование-конфига)).

### 3.3. Запуск

```bash
docker compose up -d
```

```bash
docker compose logs -f cypher
```

В логе первого запуска будет ссылка `cypher://…` для первого пользователя
(`user1`). Сервер готов, когда появится строка
`certificate ready … expires=… renews_after=…`.

### 3.4. Что в контейнере

| Что | Значение |
|---|---|
| Образ | `ghcr.io/ddday9/cypher:latest` (amd64, arm64), `distroless/static`, без shell |
| Пользователь | `nonroot` (uid 65532) |
| Порт внутри | `8443`, проброшен на `443` хоста |
| Конфиг | `/etc/cypher/server.json` в томе `cypher_cypher-data` |
| Защита | файловая система только для чтения, все capabilities сброшены, `no-new-privileges` |
| Логи | json-file, 3 файла по 10 МБ |

В образе заданы `CYPHER_CONFIG=/etc/cypher/server.json`,
`CYPHER_LISTEN=:8443`, `CYPHER_PUBLIC_PORT=443` (порт, который попадает в
ссылки), compose добавляет `CYPHER_ACME_HTTP=:8081` и
`CYPHER_FALLBACK_PROXY=http://nginx:8080`.

### 3.5. Редактирование конфига

Shell в образе нет, поэтому конфиг удобно править временным контейнером
с тем же томом:

```bash
docker run --rm -it --user 65532 -v cypher_cypher-data:/d alpine vi /d/server.json
```

Пользователи и маршрутизация применяются сами за несколько секунд; что
требует перезапуска — в [разделе 13](#13-что-применяется-без-перезапуска).
Перезапуск:

```bash
docker compose restart cypher
```

### 3.6. Обновление

```bash
docker compose pull && docker compose up -d
```

Конфиг, пользователи, сертификат и ключи лежат в томе и не теряются.

### 3.7. Резервная копия

```bash
docker run --rm -v cypher_cypher-data:/d -v "$PWD":/b alpine tar czf /b/cypher-backup.tgz -C /d .
```

## 4. Установка без Docker (systemd)

Скопируйте на сервер бинарник и папку `deploy/` (из архива релиза или
репозитория) и запустите:

```bash
sudo ./deploy/install-server.sh --domain exit.example.com --email you@example.com
```

Ретранслятор:

```bash
sudo ./deploy/install-server.sh --domain ru.example.com --upstream "cypher://КЛЮЧ@exit.example.com:443?epk=…"
```

### 4.1. Параметры install-server.sh

| Параметр | Что делает |
|---|---|
| `--domain NAME` | домен сервера; cypher сам получает и продлевает сертификат Let's Encrypt |
| `--email ADDR` | email для Let's Encrypt (необязательно) |
| `--self-signed` | самоподписанный сертификат на IP сервера, без домена — **только для проверки** (клиенту нужен `cert.pem` в `"ca"`) |
| `--binary PATH` | какой бинарник ставить (по умолчанию `cypher-linux-<arch>` рядом со скриптом или `../bin/`) |
| `--port N` | порт cypher (по умолчанию 443) |
| `--site DIR` | папка со своим сайтом-прикрытием (по умолчанию — заглушка) |
| `--add-user NAME` | добавить пользователя в существующий конфиг |
| `--no-nginx` | не ставить nginx: cypher сам слушает 80 для сертификата и сам отдаёт сайт из `/var/www/cypher` |
| `--upstream LINK` | режим ретранслятора: ссылка пользователя на выходе; заодно создаются правила маршрутизации по умолчанию |

### 4.2. Что делает скрипт

* создаёт системного пользователя `cypher`, каталоги `/etc/cypher`
  (конфиг, `root:cypher`), `/etc/cypher/acme` (сертификаты),
  `/var/lib/cypher` (базы geosite/geoip и ключ e2e — сюда служба пишет сама);
* ставит nginx: порт 80 — редирект на https и пропуск проверок Let's Encrypt
  в cypher (`127.0.0.1:8081`), `127.0.0.1:8080` — сайт из `/var/www/cypher`;
* генерирует ключ первого пользователя и пишет `/etc/cypher/server.json`;
* ставит службу `cypher.service` и запускает её, открывает порты в `ufw`,
  если он включён;
* печатает ссылку `cypher://…`.

Повторный запуск обновляет бинарник и службу, существующий конфиг не
трогает.

### 4.3. Управление службой

```bash
sudo systemctl restart cypher
```

```bash
journalctl -u cypher -f
```

```bash
sudo cypher user add phone -c /etc/cypher/server.json
```

## 5. Ручной запуск

Любой из вариантов ниже запускает сервер с готовым конфигом:

```bash
cypher run -c /etc/cypher/server.json
```

```bash
cypher serve -c /etc/cypher/server.json
```

`serve` отличается тем, что при отсутствии конфига создаёт его из
переменных окружения ([раздел 11](#11-переменные-окружения)). Файл с
секцией `server` запускает сервер, без неё — клиент. Проверить конфиг без
запуска:

```bash
cypher check -c /etc/cypher/server.json
```

## 6. Файл server.json — все параметры

Пример выхода:

```json
{
  "log": { "level": "info" },
  "server": {
    "listen": ":443",
    "acme": { "domain": "exit.example.com", "email": "you@example.com", "cacheDir": "acme", "httpListen": "127.0.0.1:8081" },
    "users": [
      { "name": "phone", "key": "…" },
      { "name": "relay", "key": "…" }
    ],
    "fallback": { "proxy": "http://127.0.0.1:8080" },
    "allowPrivate": false
  },
  "routing": {
    "rules": [ { "domain": ["geosite:category-ads-all"], "outbound": "block" } ]
  }
}
```

Пример ретранслятора — [examples/server-relay.json](../examples/server-relay.json).

Неизвестные поля — ошибка (опечатка не пройдёт незамеченной). Относительные
пути считаются от папки конфига.

### 6.1. log

| Поле | По умолчанию | Значения |
|---|---|---|
| `level` | `info` | `debug` (каждое соединение, маршрут), `info`, `warn`, `error` |

На ретрансляторе и выходе с `debug` в лог пишутся адреса назначения —
не оставляйте `debug` надолго, если это нежелательно.

### 6.2. server

| Поле | По умолчанию | Что это |
|---|---|---|
| `listen` | `:443` | адрес и порт cypher. В Docker — `:8443` (снаружи 443) |
| `acme` | — | автоматический сертификат Let's Encrypt (6.3). Взаимоисключается с `certFile`/`keyFile` |
| `certFile`, `keyFile` | — | свой сертификат (полная цепочка) и ключ в PEM. Перечитываются раз в минуту при изменении файла — продление certbot подхватится без перезапуска |
| `users` | — (обязательно, ≥ 1) | пользователи (6.4) |
| `fallback` | встроенная страница | сайт для всех без ключа (6.5) |
| `allowPrivate` | `false` | разрешить клиентам ходить на адреса самого сервера и его сети: loopback, частные (10/8, 172.16/12, 192.168/16), link-local, CGNAT (100.64/10), multicast. Проверяется после резолва домена, так что `localhost.example` → 127.0.0.1 тоже запрещён |
| `upstream` | — | сделать сервер ретранслятором (6.6) |
| `e2eKeyFile` | `e2e.key` рядом с конфигом | ключ сквозного шифрования этого сервера как выхода (6.7) |

### 6.3. server.acme

Сертификат получается при первом запуске и продлевается за 30 дней до
истечения, новый начинает использоваться сразу. certbot не нужен.

| Поле | По умолчанию | Что это |
|---|---|---|
| `domain` | — (обязательно) | домен; A-запись должна указывать на сервер |
| `email` | — | для писем Let's Encrypt о проблемах с сертификатом |
| `cacheDir` | `acme` рядом с конфигом | где хранится сертификат и аккаунт ACME. Не удаляйте: у Let's Encrypt лимит выпусков на домен |
| `httpListen` | — | где слушать проверку HTTP-01 (и редирект на https для остального). `":80"` — cypher сам на порту 80; `"127.0.0.1:8081"` / `":8081"` — порт, куда nginx с порта 80 пересылает `/.well-known/acme-challenge/` |
| `directoryURL` | Let's Encrypt | другой ACME-сервер, например staging Let's Encrypt `https://acme-staging-v02.api.letsencrypt.org/directory` для проверок без лимитов |
| `ca` | — | дополнительный корневой сертификат (PEM) для связи с ACME-сервером (свой ACME-сервер) |

Проверка домена идёт через TLS-ALPN-01 на порту `listen` (если он
доступен снаружи как 443) и через HTTP-01, если задан `httpListen`.
Если сертификат не получен, сервер повторяет попытку и пишет в лог
`certificate not obtained yet … retry_in=…`.

### 6.4. server.users

```json
"users": [ { "name": "phone", "key": "base64url-32-байта" } ]
```

| Поле | Что это |
|---|---|
| `name` | имя (для логов и правил `inboundTag`). Пустое — `user1`, `user2`, … |
| `key` | 32 случайных байта в base64url (`cypher genkey`). Ключи не должны повторяться |

Удобнее управлять командами `cypher user …` ([раздел 9](#9-пользователи)).
Ограничений по трафику и сроку нет: пользователь либо есть, либо отозван.

### 6.5. server.fallback — сайт-прикрытие

Его получают все, кто подключился без валидного ключа: браузеры,
поисковики, сканеры и проверки цензора (HTTP/1.1 и HTTP/2).

| Поле | Что это |
|---|---|
| `proxy` | URL веб-сервера, которому передаются такие соединения, например `http://127.0.0.1:8080` (nginx). Добавляются `X-Forwarded-For` и `X-Forwarded-Proto: https` |
| `dir` | папка со статическим сайтом; cypher отдаёт её сам. Пока в папке нет `index.html`, отдаётся встроенная страница. Каталоги без `index.html` не листаются |
| (ничего) | встроенная страница: `200` на `/`, `404` на остальное |

Заполните сайт правдоподобным содержимым: пустая заглушка на домене, к
которому идёт много трафика, выглядит подозрительно.

### 6.6. server.upstream — ретранслятор

Наличие секции делает сервер ретранслятором. Проще всего — одна ссылка:

```json
"upstream": { "link": "cypher://КЛЮЧ@exit.example.com:443?epk=…" }
```

`link` — ссылка пользователя, созданного на выходе (`cypher user add relay`
там). Вместо ссылки или вместе с ней можно указать те же поля, что у
cypher-outbound клиента; явные поля важнее полей из ссылки:

| Поле | По умолчанию | Что это |
|---|---|---|
| `link` | — | ссылка `cypher://` пользователя на выходе |
| `server` | из ссылки | `host:port` выхода |
| `key` | из ссылки | ключ пользователя на выходе |
| `serverName` | хост из `server` | SNI, если отличается |
| `fingerprint` | `firefox` | отпечаток TLS до выхода: `firefox`, `chrome`, `safari`, `edge`, `ios`, `android`, `random` |
| `ca` | системные | доп. корневой сертификат выхода (для самоподписанного) |
| `insecure` | `false` | не проверять сертификат выхода — только для тестов |
| `connections` | `1` | сколько TLS-соединений к выходу держать параллельно |
| `singleConnection` | `false` | строго одно соединение к выходу |
| `rotation` | `5m-20m` / `64-512` МБ / простой `1m-3m` | ротация соединений к выходу (как у клиента, [client.md](client.md)) |
| `antiFreeze` | `auto` | защита от заморозки на участке ретранслятор → выход: `auto`, `on`, `off` |
| `antiFreezeRate` | `8` | новых соединений за 10 с в режиме защиты |
| `exitPublicKey` | `epk` из ссылки | публичный ключ выхода; нужен только для печати ссылок со сквозным шифрованием (`cypher user add … -exit`) |

Все пользователи ретранслятора идут к выходу по общему соединению (или
нескольким, если `connections` > 1). Изменение `upstream` требует
перезапуска.

Подробно о ретрансляторе — [раздел 8](#8-ретранслятор-промежуточный-сервер).

### 6.7. Сквозное шифрование: ключ выхода

Каждый сервер (как потенциальный выход) держит статический ключ X25519 в
файле `e2eKeyFile` (по умолчанию `e2e.key` рядом с конфигом). Он создаётся
сам при первом запуске или первой команде `cypher user …`. Публичная
половина попадает в ссылки пользователей как `epk=…`.

* Если файл не удаётся создать или прочитать, сервер работает, но
  сквозное шифрование через него недоступно (в логе
  `end-to-end encryption through relays is off`).
* **Не теряйте и не меняйте ключ:** все ссылки со сквозным шифрованием,
  выданные через ретранслятор, содержат его публичную часть; при смене
  ключа их придётся перевыпустить.
* Ключ секретный: кто его знает, может расшифровать перехваченные
  первые сообщения сквозных сессий (содержат адрес назначения).

### 6.8. routing

Правила маршрутизации сервера. Синтаксис тот же, что у клиента; отличия —
в [разделе 7](#7-маршрутизация-на-сервере).

| Поле | По умолчанию | Что это |
|---|---|---|
| `geosite`, `geoip` | `geosite.dat`, `geoip.dat` рядом с конфигом | пути к базам |
| `geositeURL`, `geoipURL` | runetfreedom, если правила используют `geosite:`/`geoip:` | откуда скачивать базы; `"none"` — не скачивать (свои файлы) |
| `geoUpdate` | `24h` | как часто обновлять базы: `6h`, `12h`, `72h`, … или `off` |
| `domainStrategy` | `AsIs` | `AsIs` — IP-правила только для запросов по IP; `IPIfNonMatch` — если домен не совпал, сервер резолвит его и проверяет IP-правила (DNS-запрос делает сервер) |
| `rules` | — | список правил, проверяются по порядку |
| `default` | `direct` (на ретрансляторе `exit`) | действие, если ни одно правило не совпало |

## 7. Маршрутизация на сервере

Каждое соединение клиента (и каждый UDP-пакет) проверяется по правилам
сверху вниз; первое совпавшее определяет действие.

**Действия (`outbound`):**

| Действие | Где | Что происходит |
|---|---|---|
| `direct` | везде | сервер подключается к адресу сам, со своего IP |
| `block` | везде | соединение отклоняется (клиент получает «destination not allowed»), UDP-пакет отбрасывается |
| `exit` | только ретранслятор | соединение уходит на выход |

**Поля правила** (внутри поля — ИЛИ, между полями — И):

| Поле | Пример | Что совпадает |
|---|---|---|
| `domain` | `["geosite:category-ads-all", "domain:example.com"]` | домен назначения (синтаксис — ниже) |
| `ip` | `["geoip:ru", "10.0.0.0/8", "1.2.3.4", "geoip:!ru"]` | IP назначения |
| `port` | `443`, `"80,443"`, `"1000-2000"` | порт назначения |
| `network` | `"tcp"`, `"udp"`, `"tcp,udp"` | протокол |
| `inboundTag` | `["phone", "kids"]` | **имя пользователя** на этом сервере |

`process` на сервере не работает (сервер не знает программ клиента).

**Синтаксис доменов:**

| Запись | Совпадает |
|---|---|
| `geosite:google` | категория из geosite.dat |
| `geosite:google@cn` | категория с атрибутом |
| `domain:example.com` | сам домен и все поддомены |
| `full:www.example.com` | только этот домен |
| `keyword:goog` | подстрока в домене |
| `regexp:^ads\d+\.` | регулярное выражение |
| `example` (без префикса) | то же, что `keyword:` |

**IP:** `geoip:ru`, `geoip:private`, `geoip:!ru` (всё, кроме), CIDR
(`10.0.0.0/8`, `2001:db8::/32`), отдельный адрес.

**Полезные категории runetfreedom:** `geosite:ru-blocked` (заблокированное
в РФ), `geosite:ru-blocked-all`, `geosite:ru-available-only-inside`
(работает только из России), `geosite:category-ru`, `geosite:category-gov-ru`,
`geosite:category-ads-all`, `geosite:private`; `geoip:ru`,
`geoip:ru-blocked`, `geoip:ru-blocked-community`, `geoip:private`, а также
все категории v2fly (`geosite:google`, `geosite:youtube`, …).

**Важно про домены и IP.** Клиент обычно передаёт серверу домен. Правила
`ip:` к таким запросам применяются только с `domainStrategy:
IPIfNonMatch` (сервер сам резолвит домен). Запросы по IP (например, из
TUN-режима клиента без сниффинга) проверяются IP-правилами всегда.

Примеры:

```json
"rules": [
  { "domain": ["geosite:category-ads-all"], "outbound": "block" },
  { "inboundTag": ["kids"], "domain": ["geosite:category-porn"], "outbound": "block" },
  { "port": "25", "outbound": "block" }
]
```

## 8. Ретранслятор (промежуточный сервер)

### 8.1. Зачем

Клиент видит только российский IP ретранслятора: ограничения «к
зарубежным хостингам» (например, заморозка соединения после ~16 КБ) его не
касаются, а IP выхода не виден провайдеру клиента. Российские сайты
ретранслятор открывает сам — с российского IP, быстро и без «иностранного»
адреса. Если выход заблокируют, достаточно поменять `upstream` на
ретрансляторе — клиенты ничего не перенастраивают.

Ограничения: на мобильных сетях с белыми списками пропускаются конкретные
адреса, а не любой российский хостинг; российский хостинг подпадает под
СОРМ — поэтому для чувствительного трафика используйте сквозное
шифрование (8.4).

### 8.2. Пошаговая настройка

**Шаг 1. Выход** (за границей) — обычная установка ([раздел 3](#3-установка-в-docker)
или [4](#4-установка-без-docker-systemd)). Создайте на нём пользователя для
ретранслятора:

```bash
docker compose exec cypher cypher user add relay
```

Ссылка вида `cypher://КЛЮЧ@exit.example.com:443?epk=…#…` — это значение
для `CYPHER_UPSTREAM`. `epk` — публичный ключ выхода.

**Шаг 2. Ретранслятор** (в России). В `.env`:

```bash
CYPHER_DOMAIN=ru.example.com
CYPHER_UPSTREAM=cypher://КЛЮЧ@exit.example.com:443?epk=…
```

```bash
docker compose up -d
```

В логе — ссылка первого пользователя ретранслятора и строки
`relay mode: traffic routed to "exit" goes to the upstream server` и
`server routing rules applied rules=4 default=exit`. При первом запуске
скачиваются базы runetfreedom (~110 МБ), это занимает до минуты.

Без Docker: `sudo ./deploy/install-server.sh --domain ru.example.com --upstream "ССЫЛКА"`.
Вручную: добавьте в `server.json` секцию `upstream` (6.6) и правила (8.3).

**Шаг 3. Пользователи** — см. 8.4.

### 8.3. Правила ретранслятора

При первом запуске с `CYPHER_UPSTREAM` (или `--upstream`) создаются такие
правила:

```json
"routing": {
  "geositeURL": "https://github.com/runetfreedom/russia-v2ray-rules-dat/releases/latest/download/geosite.dat",
  "geoipURL": "https://github.com/runetfreedom/russia-v2ray-rules-dat/releases/latest/download/geoip.dat",
  "rules": [
    { "domain": ["geosite:ru-blocked"], "outbound": "exit" },
    { "ip": ["geoip:ru-blocked"], "outbound": "exit" },
    { "domain": ["geosite:category-ru", "geosite:ru-available-only-inside", "domain:ru", "domain:xn--p1ai", "domain:su"], "outbound": "direct" },
    { "ip": ["geoip:ru"], "outbound": "direct" }
  ],
  "default": "exit"
}
```

Порядок важен: заблокированные в РФ сайты на `.ru` должны уйти на выход
раньше, чем сработает «`.ru` — напрямую».

Варианты:

* **Всё через выход** — удалите `rules` (или оставьте пустым списком):
  без правил ретранслятор отправляет всё на выход.
* **Через выход только заблокированное**, остальное — с ретранслятора:

  ```json
  "rules": [
    { "domain": ["geosite:ru-blocked"], "outbound": "exit" },
    { "ip": ["geoip:ru-blocked"], "outbound": "exit" }
  ],
  "default": "direct"
  ```

* **Реклама блокируется для всех** — первым правилом
  `{ "domain": ["geosite:category-ads-all"], "outbound": "block" }`.
* **Отдельные правила для пользователя** — `inboundTag` с его именем на
  ретрансляторе.

Правила клиента проверяются раньше: если в nevio выбрано «Россия
напрямую», российские сайты пойдут прямо с компьютера пользователя и до
ретранслятора не дойдут. На ретранслятор попадает только то, что клиент
отправил «через VPN».

### 8.4. Пользователи ретранслятора: два режима

| | Режим A (обычный) | Режим B (сквозное шифрование) |
|---|---|---|
| Где заводится пользователь | только на ретрансляторе | на выходе **и** на ретрансляторе |
| Подходит для клиентов | любых, включая v0.1 | nevio / cypher v0.3+ |
| Ретранслятор видит адреса назначения | да | да (нужно для правил); со «скрытыми адресами» — нет |
| Ретранслятор видит данные | да (HTTPS сайтов зашифрован и так) | **нет** для трафика на выход |
| Ретранслятор может выдать себя за пользователя перед выходом | — (выход видит пользователя `relay`) | **нет** |
| Правила и отзыв на выходе | общие для всех (пользователь `relay`) | для каждого пользователя |

**Режим A** — на ретрансляторе:

```bash
docker compose exec cypher cypher user add phone
```

**Режим B.** Сначала на **выходе**:

```bash
docker compose exec cypher cypher user add phone
```

Скопируйте напечатанную ссылку. Затем на **ретрансляторе**:

```bash
docker compose exec cypher cypher user add phone -exit "ССЫЛКА_С_ВЫХОДА"
```

Вместо ссылки в `-exit` можно передать просто ключ пользователя на выходе.
Получится ссылка `cypher://…@ru.example.com:443?ek=…&epk=…#ru.example.com · phone (e2e)`
— её и отдайте пользователю. Для существующего пользователя ретранслятора:
`cypher user link phone -exit "…"`.

**Скрытые адреса.** Добавьте к ссылке режима B `&hd=1` (или в конфиге
клиента `"hideDestinations": true`): ретранслятор не увидит даже адресов,
но и правила применить не сможет — весь трафик уйдёт на выход. Требует
выход v0.3+.

Отзыв: в режиме A — на ретрансляторе; в режиме B — на любом из двух
серверов (на выходе — отключает этого пользователя на всех
ретрансляторах сразу).

### 8.5. Как это работает

* Ретранслятор подключается к выходу как обычный клиент: одно
  мультиплексированное TLS-соединение (с ротацией, паузами при сбоях и
  защитой от заморозки, как у клиента), отпечаток Firefox.
* В режиме B клиент шифрует поток для выхода (Noise NK: X25519,
  ChaCha20-Poly1305, BLAKE2s) и аутентифицируется ключом пользователя на
  выходе. Ретранслятор по адресу решает маршрут: `exit` — пересылает байты
  не читая, `direct`/`block` — обслуживает соединение сам, как обычный
  сервер.
* UDP: в режиме A маршрут выбирается для каждого пакета, в режиме B — по
  первому адресату потока.
* Протокол — [protocol.md, раздел 8](protocol.md#8-ретранслятор-и-сквозное-шифрование).

### 8.6. Совместимость версий

| Клиент | Ретранслятор | Выход | Результат |
|---|---|---|---|
| любой, ссылка ретранслятора | v0.3+ | v0.3+ | режим A |
| v0.3+, ссылка с `ek`/`epk` | v0.3+ | v0.3+ | режим B |
| v0.3+, ссылка с `ek`/`epk` | v0.3+ | v0.1–v0.2 | ретранслятор сам переходит на режим A |
| v0.3+, `hd=1` | v0.3+ | v0.1–v0.2 | не работает (выходу нужно сквозное шифрование) |
| любой | — | любой | прямое подключение, как раньше |

### 8.7. Смена выхода

1. Поднимите новый выход, создайте на нём пользователя `relay`.
2. На ретрансляторе замените `server.upstream.link` и перезапустите
   (`docker compose restart cypher`).
3. Пользователям режима A ничего делать не нужно. Для режима B нужны новые
   ссылки (`cypher user link NAME -exit …`): у нового выхода другой `epk` и
   свои пользователи.

## 9. Пользователи

Команды работают с конфигом и применяются запущенным сервером за
несколько секунд, без перезапуска; отозванный пользователь отключается
сразу (в том числе его сквозные сессии через ретрансляторы).

| Команда | Что делает |
|---|---|
| `cypher user add NAME` | создать пользователя с новым ключом и напечатать ссылку |
| `cypher user list` | все пользователи со ссылками |
| `cypher user link NAME` | ссылка одного пользователя |
| `cypher user revoke NAME` | удалить пользователя (последнего удалить нельзя) |

Параметры (после имени):

| Параметр | Что это |
|---|---|
| `-c FILE` | конфиг (по умолчанию `$CYPHER_CONFIG` или `/etc/cypher/server.json`) |
| `-host HOST` | адрес сервера в ссылке, если не домен из `acme` (например IP) |
| `-exit KEY\|LINK` | только на ретрансляторе, для `add`/`link`: ссылка со сквозным шифрованием для пользователя с этим ключом (или ссылкой) на выходе |

Порт в ссылке — `CYPHER_PUBLIC_PORT`, иначе порт из `listen`.

В Docker команды выполняются в контейнере:

```bash
docker compose exec cypher cypher user list
```

Ссылки на выходе содержат `epk` — это нормально: обычным клиентам он не
мешает, а ретранслятору нужен.

## 10. Команды cypher

| Команда | Что делает |
|---|---|
| `cypher serve [-c FILE]` | запустить сервер; если конфига нет — создать из переменных окружения |
| `cypher run -c FILE` | запустить сервер или клиент (по содержимому конфига) |
| `cypher check -c FILE` | проверить конфиг и выйти |
| `cypher genkey` | новый ключ пользователя |
| `cypher user add\|list\|link\|revoke` | пользователи ([раздел 9](#9-пользователи)) |
| `cypher link …` | собрать ссылку вручную ([client.md](client.md#4-ссылка-cypher)) |
| `cypher version` | версия |

## 11. Переменные окружения

Все, кроме `CYPHER_CONFIG` и `CYPHER_PUBLIC_PORT`, читаются только при
создании конфига (`cypher serve` без `server.json`).

| Переменная | По умолчанию | Что это |
|---|---|---|
| `CYPHER_CONFIG` | `/etc/cypher/server.json` | путь к конфигу (для `serve` и `user`) |
| `CYPHER_DOMAIN` | — (обязательна) | домен сервера → `acme.domain` |
| `CYPHER_EMAIL` | — | → `acme.email` |
| `CYPHER_LISTEN` | `:443` (в образе `:8443`) | → `listen` |
| `CYPHER_PUBLIC_PORT` | порт из `listen` (в образе `443`) | порт, который пишется в ссылки |
| `CYPHER_ACME_HTTP` | — (в compose `:8081`) | → `acme.httpListen` |
| `CYPHER_ACME_DIRECTORY` | Let's Encrypt | → `acme.directoryURL` |
| `CYPHER_ACME_CA` | — | → `acme.ca` |
| `CYPHER_FALLBACK_PROXY` | — (в compose `http://nginx:8080`) | → `fallback.proxy` |
| `CYPHER_SITE` | `/var/www/cypher` | → `fallback.dir`, если нет `CYPHER_FALLBACK_PROXY` |
| `CYPHER_USER` | `user1` | имя первого пользователя |
| `CYPHER_LOG` | `info` | → `log.level` |
| `CYPHER_UPSTREAM` | — | ссылка пользователя на выходе: сервер — ретранслятор, создаются правила 8.3 |
| `CYPHER_BLOCK_RU` | `0` | `1` — правила «российские домены и IP → block» (для выхода; на ретрансляторе игнорируется) |

## 12. Файлы сервера

| Файл | Docker | systemd | Что это |
|---|---|---|---|
| `server.json` | `/etc/cypher/` (том) | `/etc/cypher/` | конфиг, ключи пользователей — **секрет** |
| `acme/` | `/etc/cypher/acme/` | `/etc/cypher/acme/` | сертификат и аккаунт Let's Encrypt |
| `e2e.key` | `/etc/cypher/` | `/var/lib/cypher/` (новые установки) | ключ сквозного шифрования — **секрет** |
| `geosite.dat`, `geoip.dat` | `/etc/cypher/` | `/var/lib/cypher/` (ретранслятор) | базы для правил |
| сайт-прикрытие | `./site` рядом с compose | `/var/www/cypher` | `index.html` и прочее |

Резервная копия `server.json`, `acme/` и `e2e.key` позволяет восстановить
сервер без перевыпуска ссылок.

## 13. Что применяется без перезапуска

Сервер проверяет `server.json` и файлы баз каждые 3 секунды (изменение
применяется, когда файл не меняется ещё одну проверку).

| Изменение | Без перезапуска |
|---|---|
| `users` (добавить, отозвать) | да; отозванные отключаются сразу |
| `routing.rules`, `default`, `domainStrategy` | да |
| новые `geosite.dat`/`geoip.dat` (в т. ч. от автообновления) | да |
| `geositeURL`, `geoipURL`, `geoUpdate` | нет — перезапуск |
| первые правила с `geosite:`/`geoip:` на сервере, где правил не было | правила применятся, а базы скачаются после перезапуска |
| `listen`, `acme`, сертификат-файлы (путь), `fallback`, `allowPrivate`, `upstream`, `e2eKeyFile` | нет — перезапуск (содержимое `certFile` перечитывается само) |

Если новый конфиг или база с ошибкой, в лог пишется ошибка и продолжают
действовать прежние пользователи и правила.

## 14. Типовые задачи

### 14.1. Свой сайт-прикрытие

Docker: замените содержимое `./site` (рядом с `docker-compose.yml`),
перезапуск не нужен. systemd: `/var/www/cypher` или `--site DIR` при
установке.

### 14.2. Другой порт

Docker: в `docker-compose.yml` поменяйте `"443:8443/tcp"` на
`"8444:8443/tcp"` и добавьте в `environment` `CYPHER_PUBLIC_PORT: "8444"`
(он влияет только на порт в печатаемых ссылках и читается при каждой
команде `cypher user …`), затем `docker compose up -d`. systemd:
`--port 8444`. Нестандартный порт сам по себе заметен —
меняйте, только если на 443 проблемы.

### 14.3. Проверка без лимитов Let's Encrypt

`CYPHER_ACME_DIRECTORY=https://acme-staging-v02.api.letsencrypt.org/directory`
— сертификат будет недоверенным, но лимиты не тратятся. Для боевого
сертификата удалите `acme/` и уберите `directoryURL`.

### 14.4. Без домена (только для проверки)

`install-server.sh --self-signed`: сертификат на IP. Клиенту нужен
`/etc/cypher/cert.pem` в поле `"ca"`. Для постоянной работы не годится:
самоподписанный сертификат сразу выдаёт нестандартный сервер.

### 14.5. Ограничить пользователя

```json
{ "inboundTag": ["guest"], "port": "25,465,587", "outbound": "block" }
```

### 14.6. Не светить IP выхода на российских сайтах

В 2026 банили IP VPN-выходов, замеченные на российских сервисах. Клиент
по умолчанию и так отправляет российское напрямую. Чтобы сервер вообще не
ходил на российские адреса: `CYPHER_BLOCK_RU=1` при создании или правила:

```json
"rules": [
  { "domain": ["geosite:category-ru", "domain:ru", "domain:xn--p1ai", "domain:su"], "outbound": "block" },
  { "ip": ["geoip:ru"], "outbound": "block" }
]
```

### 14.7. Проверить сервер с другого Linux-хоста

```bash
./deploy/test-client.sh --server exit.example.com:443 --key КЛЮЧ
```

Проверяет, что без ключа отдаётся сайт, TCP и UDP через туннель работают и
выход идёт с IP сервера. Параметры: `--ca FILE` (самоподписанный),
`--binary PATH`.

## 15. Диагностика

Логи: `docker compose logs -f cypher` или `journalctl -u cypher -f`. Для
подробностей — `"log": {"level": "debug"}` (применяется после
перезапуска).

| Сообщение / симптом | Причина и что делать |
|---|---|
| `certificate not obtained yet …` | A-запись не указывает на сервер, закрыты порты 80/443, или порт 80 занят другим сервисом. Проверьте `dig +short ДОМЕН` и файрвол |
| В браузере сертификат недоверенный | используется staging (`directoryURL`) или самоподписанный |
| Клиент «подключается», но сайты не открываются | проверьте время на сервере и клиенте (допуск ±120 с), ключ, порт; в логе сервера должно быть `client connected` |
| `not a client, serving fallback` (в `debug`) | подключение без валидного ключа (браузер, сканер или неверный ключ клиента) |
| `server routing rules not applied` | ошибка в правилах (неизвестная категория, нет базы); действуют прежние |
| `geo files unavailable …` | нет доступа к GitHub для скачивания баз; положите файлы вручную и укажите `"geositeURL": "none"` |
| `exit server unreachable` (ретранслятор) | выход недоступен: проверьте `upstream`, что пользователь `relay` существует на выходе, доступность выхода с ретранслятора |
| `end-to-end encryption through relays is off` | не удалось создать `e2e.key`: права на папку (systemd: `/var/lib/cypher`, владелец `cypher`) |
| Ссылка `-exit` не печатается: `the upstream has no exit public key` | в `upstream.link` нет `epk`: возьмите ссылку, напечатанную выходом v0.3+, или укажите `exitPublicKey` |
| Пользователь не добавился | правьте конфиг командами `cypher user …` или следите за JSON: при ошибке остаются прежние пользователи (сообщение в логе) |

## 16. Безопасность

* `server.json` и `e2e.key` — секреты. Права: Docker — том доступен только
  контейнеру; systemd — `root:cypher`, 660/640.
* Каждому устройству — свой пользователь: так можно отозвать одно, не
  трогая остальные.
* Сервер по умолчанию не пускает клиентов в свою локальную сеть
  (`allowPrivate: false`).
* Время на сервере должно быть точным (NTP): аутентификация допускает
  расхождение ±120 секунд.
* Не оставляйте `debug`-логи на ретрансляторе надолго: в них адреса
  назначения.
* Ретранслятор в РФ подпадает под требования российского законодательства
  к хостингам. Сквозное шифрование (режим B) защищает содержимое трафика на
  выход, но не скрывает факт подключений и (без `hd=1`) адреса назначения.
